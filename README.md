# NEXT STOP Network

Public-facing MVP for NEXT STOP — a hostel network where a **digital NEXT PASS**,
generated by scanning a partner hostel's QR code at reception, unlocks the next
partner's direct rate.

Launch market: **Spain (Valencia first)**, plus the Balkan backpacker trail.

## Stack

- Next.js 16 (App Router) + TypeScript
- Tailwind CSS v4 — design tokens live in `src/app/globals.css` under `@theme`
- `next/image` with remote Unsplash images; no runtime dependencies beyond React

## Çalıştırma

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # production build
npm run lint
npx tsc --noEmit
```

## Data architecture

All repeated content is centralised in `src/data/` and rendered from typed
arrays. Changing Valencia in one place updates the home page, the destinations
index, the city page, routes, guides and search at once.

```
src/data/
  destinations.ts   # 16 cities + countries, lookups, featured/popular flags
  hostels.ts        # 16 hostels, rooms, amenities, reviews, lookups
  routes.ts         # 4 routes with stops and transport legs
  guides.ts         # 8 editorial guides with sections
  faq.ts            # FAQ categories and items
  partners.ts       # partner benefits, flow, resources, comparison
  next-pass.ts      # NEXT PASS steps, benefits, example journey, sample pass
  site.ts           # navigation, footer, socials, contact subjects
src/lib/search.ts   # accent-insensitive autocomplete over destinations
```

## The NEXT PASS model

NEXT PASS is **digital**. There is no physical card and no membership.

```
STAY  →  SCAN  →  GET YOUR PASS  →  DISCOVER  →  BOOK  →  CONTINUE
```

1. The traveller stays at a NEXT STOP partner hostel.
2. That hostel has its own unique NEXT STOP QR code on display at reception.
3. The traveller scans it with their phone camera.
4. NEXT STOP opens on that phone.
5. A short flow generates a unique digital pass code, e.g. `NS-VLC-4K7Q`.
6. The pass is shown on the traveller's phone.
7. Entering that code when booking the next partner hostel unlocks its rate.

The QR carries the hostel's partner/referral identifier, so the pass records
where the journey continued from and the onward booking is attributed to that
hostel. That identifier is the seam a real API drops into later — the UI is
already shaped around it, and no fake backend simulates it today.

The three components that carry this model:

- `ui/QrGraphic.tsx` — a decorative, deterministic QR matrix. **Not scannable**,
  and labelled as an illustration wherever it appears. Real per-hostel codes
  replace it.
- `ui/DigitalPass.tsx` — `PhoneFrame`, `DigitalPassScreen`, `DigitalPassPhone`.
  The pass is always rendered inside a phone shell so it can never read as
  something printed.
- `sections/ScanFlow.tsx` — the reception QR → arrow → phone explainer used on
  `/next-pass`, `/how-it-works`, `/partners`, `/routes` and `/about`.

The canonical step copy lives once in `src/data/next-pass.ts` (`nextPassSteps`
for the full six, `homeJourney` for the condensed five on the home page).

## Search

The hero search box is a real combobox: accent-insensitive matching
(`malaga` → Málaga), country queries that expand to their cities
(`spa` → Spain + 9 Spanish cities), Arrow Up/Down/Enter/Escape keyboard
navigation, a designed no-result state, and routing to `/destinations/[slug]`.

## Demo / mock scope

This is a front-end MVP. The following are deliberately demo-only:

- **All hostel, price, rating and review data** is illustrative — no real
  partner agreements or live rates. Marked in code and surfaced via `DemoNote`.
- **Booking** — the NEXT PASS code field and “Book with NEXT PASS” show a
  preview notice; no booking or payment backend exists.
- **QR codes and passes** — every QR on the site is a decorative illustration
  and `NS-VLC-4K7Q` is a made-up sample code. No pass is generated, stored or
  validated anywhere.

Copy across the site deliberately says nothing about **how** a scan opens NEXT
STOP (browser or app) — a native app is planned, so the wording stays neutral
(“NEXT STOP opens on your phone”) and makes no “no app required” promise.
- **Login** — `/partners/login` never authenticates and sends nothing.
- **Forms** — partner application, contact and newsletter forms validate and
  show success states client-side only.
- **Map** — the hostel location block is a styled placeholder, not a map SDK.
- **Partner resource downloads** — UI only.
- **Legal pages** — draft product copy, not legal advice.

## Images

Photos load from the Unsplash CDN (`images.unsplash.com`, allow-listed in
`next.config.ts`). To use your own, replace the `image` / `heroImage` / `images`
fields in `src/data/*.ts`, or drop files in `public/` and reference `/…` paths.

## Fonts

Inter + Poppins load from Google Fonts via a `<link>` in `src/app/layout.tsx`.
Swap to `next/font/google` if you prefer self-hosted fonts.
